# 專案優化盤點與執行順序

日期：2026-10-06。這一批完成程式盤點、測試基準與一項輸入修正；不代表所有玩法、畫面或效能已驗收。

## 方向與限制

- 保留現有官方關卡結構，不設計或改造地圖。
- 美術沿用程式繪製的方塊語言，不使用 imagegen。背景維持低對比，玩家、危險與可互動物優先。
- 每世界至少五類可辨識環境物件，可共用零件；靠形狀、尺度、配置與用途變化，不靠大量粒子。
- 設備落在基座、樓板或有可見懸吊支架；遠中近層具有一致的空間與視差邏輯。
- 每批先有可驗證的問題與完成條件，再擴大套用。

## 本次證據與處理

| 項目 | 現況／證據 | 處理 |
| --- | --- | --- |
| 暫停後誤發射 | `PlayerInput.release_all()` 清除按鍵狀態，但留下 `_prev_shoot`；恢復取樣會產生不存在的放開事件。新增測試先重現失敗。 | 已重設前次跳躍與射擊狀態，補三項輸入測試。 |
| 瞄準預覽不完全符合實際飛行 | `AimLayer` 從玩家中心開始且每 tick 只取終點；`PlayerSystem._fire` 有槍口位移及退避，`ProjectileSystem._sweep` 每最多 10 單位檢查碰撞。 | 下一批優先統一起點與首次撞擊預測。不能把目前線條當準確命中保證。 |
| 重試輸入邊界 | `GameScreen._restart()` 重設模擬與時間，未清除輸入緩衝。 | 尚未重現玩家可見問題；先測同幀重試＋跳躍／放開射擊，不直接判定為 bug。 |
| 背景維護成本 | 五個 Boss 場景及設備集中在 `backdrop_layer.gd`，世界分支與繪圖混合。 | 視覺定稿後抽出配置和共用設備繪製；避免現在進行整體重寫。 |
| 戰鬥畫面驗收不足 | 現有背景截圖主要涵蓋入口及鏡頭平移，無法代表激烈戰鬥時的辨識度。 | 補五場實際戰鬥的固定取景驗收。 |

預設替代按鍵有既有測試保護；尚未證明它們是錯誤，不在本次任意取消。舊生成圖仍存在資產目錄；應先核對引用，再決定封存，不直接刪除。

## 分批執行清單

### 第一批：操作可信度（本次已開始）

1. 已修正暫停／失焦共用輸入清除流程中的歷史狀態殘留。
2. 抽出無副作用的發射起點及首次撞擊預測，供模擬與瞄準線共用。預測不得破壞方塊、改變亂數或 Boss 狀態。
3. 驗證貼牆、斜射、薄牆、尖刺與地圖邊界；彈力反射和 Boss 命中要明確界定預覽支援範圍。
4. 驗證重試、暫停、失焦、慢速與高速設定下的按鍵邊緣；只修正重現的問題。

完成條件：預覽所宣告支援的情況與實際發射一致；取消瞄準不誤射；短按不漏掉、同一事件不重複消耗。

### 第二批：五世界視覺與空間

1. 為每個世界建立設備清單：主設備、輔助設備、管線、支撐結構、牆面構件至少五類；先核對目前已有內容。
2. 固定遠景牆體、中景大設備與近景附屬構件的對比層級；避免近景遮住操作區。
3. 檢查設備基座、接管和支架，禁止看似懸空又無支撐的物件。
4. 使用固定種子安排疏密與組合，保留休息區；避免五類設備每一屏全部塞滿。
5. 每世界取入口、戰鬥、鏡頭位移三組畫面，包含瞄準線、Boss 攻擊和玩家受傷狀態。

完成條件：五世界能從輪廓與構造辨認；危險和玩家始終清楚；鏡頭移動不露接縫或使設備漂浮。先以一場完成標準，再推廣其餘四場。

### 第三批：Boss 與回饋

1. 盤點五場 Boss 的警示、出招、命中、受傷、階段切換及死亡回饋。
2. 優先補足無法從畫面判讀的狀態；整合聲音、輪廓及短暫動作，不堆粒子。
3. 驗證子彈時間、暫停與重試不留下攻擊狀態或重複獎勵。

完成條件：各場有辨識度，攻擊前後狀態能被理解；已有測試以外的時序問題有重現案例與回歸保護。是否調整難度需由實玩證據決定。

### 第四批：效能與維護

1. 在同一機器、解析度和固定戰鬥區段量測平均／P95 幀時間、繪製呼叫與記憶體，先留下基準。
2. 根據分析器結果再做可視區裁切、靜態背景快取或物件重用，避免無證據優化。
3. 將背景配置、共用零件、特殊場景分離，保留原畫面對照。
4. 核對世界顯示順序、內部 slot、Boss 與背景映射；維持存檔 ID 相容。

完成條件：同條件量測有改善且無畫面／玩法退步；不以無頭測試結果宣稱穩定 FPS。

### 第五批：交付品質

1. 驗證設定、進度與關卡存檔的損壞回復和版本相容。
2. 檢查 UI 縮放、視窗切換、重新綁鍵與初次操作提示。
3. 核對有效素材引用，更新預覽頁與操作文件，再封存失效素材。
4. 對正式匯出版本執行啟動、五世界進入、Boss、重試與存讀檔檢查。
