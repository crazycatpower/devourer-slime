# 網頁版的缺陷與 Godot 版的處置

移植的原則是：保留遊戲設計與手感數值，不把網頁版的缺陷帶過來。這份清單列出讀網頁版原始碼時找到的每一個缺陷，以及 Godot 版怎麼處理。第五、六節是**沒有更動**的部分：需要設計者自己決定的觀察，以及刻意保留的行為。第七節列出會改變玩法、試玩時要特別留意的修正。

「補丁」欄的名稱對應 `tools/parity/make_reference.mjs` 裡的具名補丁。凡是會改變模擬結果的修正，都同步套用在對照測試的參考引擎上，所以每一處與網頁版的偏差都有紀錄。

## 一、遊戲邏輯

| # | 網頁版的缺陷 | Godot 版的處置 | 補丁 / 測試 |
| --- | --- | --- | --- |
| 1 | **遊戲速度綁定螢幕更新率。** 主迴圈每次 `requestAnimationFrame` 就前進一個 tick，沒有用到經過的時間。在 144 Hz 螢幕上整個遊戲快 2.4 倍。 | 模擬固定每秒 60 tick，繪製另外依螢幕更新率內插。 | `fixed-tick` |
| 2 | **玩法讀取真實時鐘。** 首領的擺盪、護盾公轉、蓄力閃爍用 `Date.now()`，不受暫停、子彈時間、遊戲速度影響。暫停回來後護盾位置會跳。 | 改用由 tick 數算出的模擬時鐘。 | `gameplay-clock` |
| 3 | **首領貼著右牆會懸空。** 首領落地判定多算了右邊一欄；貼著右牆時那一欄是邊界鋼鐵，於是它在半空中「落地」並停在牆上。 | 只檢查首領身體實際覆蓋的欄位。 | `boss-right-edge-column`；`test_boss_does_not_hang_on_the_right_wall` |
| 4 | **餵給首領的方塊沒有消失。** 被 W4 首領吸收的方塊只被標記為 dead，卻繼續飛行。 | 被吸收的方塊立即移除。 | `absorbed-projectiles-removed` |
| 5 | **一顆方塊可以用兩次。** 方塊打中首領格子後，同一個 tick 還會繼續對關卡做碰撞，可能同時填進首領又落地成一塊新方塊。 | 打中首領就停止處理。 | `projectile-stops-at-boss`；`test_block_fed_to_boss_is_consumed_exactly_once` |
| 6 | **落石範圍用了舊的畫布寬度。** 鏡頭後來拉遠成 1040 單位寬，但首領落石仍用 960 計算可見欄位，畫面最右側永遠不會落石。 | 使用實際的可見寬度。 | `drops-use-view-width` |
| 7 | **死掉的同時可以過關。** 同一個 tick 碰到尖刺與終點，會顯示「過關」，75 tick 後關卡卻重來。 | 死亡的那個 tick 不判定過關。 | `no-win-while-dying`；`test_no_win_on_the_tick_the_player_dies` |
| 8 | **重來時殘留上一輪的狀態。** `resetLevel` 沒有重設著地、土狼時間、彈牆鎖定、面向，重生後的前幾個 tick 可能在空中起跳或無法移動。 | 每次重來都建立全新的玩家狀態。 | `full-player-reset`；`test_reset_gives_a_clean_player` |
| 9 | **首領登場時史萊姆凍結變形。** 登場動畫期間玩家邏輯提早返回，擠壓變形不再回彈，史萊姆會維持當下被壓扁或拉長的樣子好幾秒。 | 登場期間繼續回彈。 | `slime-relaxes-during-boss-intro` |
| 10 | **比視野窄的關卡靠左顯示。** 鏡頭拉遠後，25 格寬的關卡右邊多出一條空白。 | 比視野小的關卡置中；鏡頭一開始就對準玩家中心。 | `camera-centres-small-levels`；`test_camera_centres_levels_smaller_than_the_view` |
| 11 | **首領程式寫死座標。** 首領出生欄位、W1 的土堆、W2/W3 被擊敗後的獎盃都寫死成標準競技場的座標。在較小的自訂關卡裡會把終點寫進邊界或寫到格子外面，首領也會生在地圖外。 | 出生點與獎盃位置會收進關卡內部，所有寫入都有邊界檢查，不會覆蓋邊界。標準競技場的結果不變。 | `test_boss_arena_writes_stay_inside_small_levels` |
| 12 | **子彈時間可能卡住。** 按住射擊時暫停或切換視窗，放開的事件可能遺失。 | 暫停與失焦時清掉按住狀態；射擊鍵沒按著時模擬不會停留在子彈時間。 | — |
| 13 | **首領的子彈飛出地圖後永遠存在。** 敵方子彈只在撞到東西時移除。 | 飛離關卡太遠的子彈會被清掉。 | — |
| 14 | **沒有起點的關卡讓玩家生在牆裡。** 找不到 `P` 時起點是 (0, 0)，也就是左上角的鋼鐵裡。 | 找不到起點時使用第一個空格。 | `test_missing_start_marker_falls_back_to_a_free_cell` |
| 15 | **打到首領已填滿的格子，方塊憑空消失。** 程式替方塊算好了反彈（註解寫「bounce off it!」），接著卻把它移除；W4 首領自己走過去碰到方塊時則真的會彈開，兩處規則相反。 | 一律彈開，方塊留在場上，落地後可以再吃。從下方打中會往下彈，不再穿過首領身體冒到頂上。 | `blocks-deflect-off-boss`；`test_block_bounces_off_an_occupied_boss_cell` |
| 16 | **在窄處貼臉吐方塊，玩家會穿牆。** 方塊落在玩家身上時，程式把玩家往旁邊挪，卻沒檢查那裡是不是實心。在一格高的通道朝下吐、或一格寬的豎井朝旁邊吐，玩家被塞進牆裡，再被碰撞邏輯一格一格頂穿整面牆（三格厚的鋼鐵 3 tick 穿過）。 | 挪過去的位置不是空的，方塊就碎掉，玩家留在原地。 | `spit-block-never-pushes-into-walls`；`test_spit_in_a_tunnel_never_pushes_the_player_through_the_wall` |
| 17 | **踩彈力方塊時按跳躍，彈得更低。** 離彈力方塊 24 單位內就算「可以跳」，下墜途中也一樣，於是跳躍在落地前就觸發，把即將發生的彈跳換成一次普通跳躍（從 400 高落下：390 變成 163）。彈起後按跳躍也會把較大的彈跳速度蓋掉。 | 下墜途中不算，按鍵留在緩衝裡等彈跳發生；彈跳比跳躍強時不觸發跳躍，比較弱時照常補成完整的跳躍。 | `jump-never-weakens-bounce`；`test_jump_never_weakens_a_bounce`、`test_a_jump_still_adds_to_a_weak_bounce` |
| 18 | **土狼時間與跳躍緩衝比註解寫的短。** 註解寫 4 幀與 12 幀，但計時器先遞減才讀取，實際是 3 與 10。 | 實際長度等於寫明的 4 與 12。 | `jump-timers-full-window`；`test_coyote_time_and_jump_buffer_last_what_they_say` |
| 19 | **首領瞄準落點時沒算天花板。** 水平速度用完整拋物線的滯空時間計算，但首領升到天花板就提早落下。W4 的大跳只飛到目標距離的 45%，「精準跳」約 52%。 | 用這次跳躍真正的滯空時間計算。 | `boss-leaps-account-for-ceiling`；`test_boss_leap_lands_where_it_aimed_despite_the_ceiling` |
| 20 | **水平後座力只有一個 tick。** 程式把水平後座力特地乘上 1.8（註解寫「strengthen horizontal recoil force!」），但走路邏輯每個 tick 都重設水平速度，結果朝旁邊吐只後退 18 單位，朝下吐卻能上升 100 單位。 | 在空中時，水平後座力會延續幾個 tick 逐漸衰減（總共約三格），撞牆或落地即止。站在地上吐的行為不變。 | `airborne-recoil-carries`；`test_recoil_carries_in_the_air_but_not_on_the_ground` |
| 21 | **首領戰每次重來都要重看完整登場。** 登場最長 3 秒，期間玩家不能動。 | 同一關看過一次之後，登場縮短為半秒。重新進入關卡會再完整播放。 | `retry-shortens-boss-intro`；`test_retry_shortens_the_boss_entrance` |
| 22 | **W2 首領掉出地圖再回來時，玩家被定住兩秒。** 沿用了開場登場的凍結，但這時地板已經有洞，定在半空的玩家會直直掉下去。 | 首領回場時玩家保有操作，也不再顯示全螢幕警告。 | `boss-reentry-keeps-player-control`；`test_player_keeps_control_when_the_world_2_boss_returns` |

## 二、程式架構

| 網頁版的問題 | Godot 版的做法 |
| --- | --- |
| 模擬、繪製、輸入、編輯器全在一個 5,255 行的檔案裡，狀態是模組層級的全域變數。 | 分層：純邏輯的模擬核心、服務、繪製、畫面。一檔一類別。 |
| 首領行為靠散落各處的 `currentPlayingSlot === 10 / 20 / 30 / 40` 判斷。 | 首領種類是一個列舉，每個首領一個檔案，格子與首領的對應只記在一處。 |
| 繪製函式裡有邏輯副作用：鏡頭跟隨、震動衰減、產生粒子都在 `draw()` 內，速度隨更新率變化。 | 繪製層只讀不寫。鏡頭屬於模擬，每個 60 Hz 畫面更新一次。 |
| 為了內插，繪製前暫時改寫模擬物件的座標，畫完再改回來。 | 內插在繪製層計算，不動模擬狀態。 |
| `any` 型別、未使用的欄位與函式（`rotateBossGridClockwise`、`MOVE_ACCEL`、沒被引用的 `LevelCard` / `BossCard` 元件、永遠到不了的分支）。 | 全面標註型別並把型別警告設為錯誤；沒有用到的程式不移植。 |
| 沒有任何測試。 | 單元測試、與網頁版引擎的逐 tick 對照測試、端到端冒煙測試。 |
| 專案範本的殘留：套件名稱 `react-example`、網頁標題「My Google AI Studio App」、用不到的 Gemini API 金鑰與 `express`、`@google/genai` 相依。 | 不適用於 Godot 版。 |

## 三、操作與介面

| 網頁版的缺陷 | Godot 版的處置 |
| --- | --- |
| 過關畫面寫「Press [SPACE]」，實際要按的是跳躍鍵（預設 W），空白鍵沒有作用。 | 顯示實際綁定的按鍵；Enter 與空白鍵也能繼續。 |
| 暫停選單開著時按重來鍵，背景的關卡會重來。 | 暫停時遊戲不接收輸入。 |
| 重新綁定按鍵時，按下的鍵同時也會觸發遊戲裡的動作（例如把某鍵綁成「重來」的瞬間關卡就重來）。 | 等待綁定時，下一個按鍵只屬於設定畫面。 |
| 設定畫面能把動作綁到滑鼠中鍵，但遊戲只認左右鍵，綁了就失效。 | 滑鼠左、中、右鍵與側鍵都能用。 |
| 兩個動作可以綁到同一個鍵（例如吞噬與吐出），其中一個會失效。 | 與同時生效的動作衝突時，兩者自動互換按鍵。上與跳躍共用 W 是原本的設計，予以保留。 |
| Esc 可以被綁成動作，同時又會關閉選單。 | Esc 保留給暫停與取消。 |
| 音量、子彈時間、按鍵會保存，遊戲速度不會。 | 一併保存。 |
| 只有進入關卡後才能開設定。 | 主選單也能開設定。 |
| 視窗失去焦點時，按住的鍵會卡住。 | 失焦時自動暫停並清掉按住狀態。 |
| W3 首領的外框沒有畫出來（畫完玻璃紋路後，外框的路徑已被取代）。 | 外框正常繪製。 |
| W3 的護盾畫在首領擠壓變形的座標系裡，首領變形時護盾的顯示位置與實際判定位置不一致。 | 護盾畫在實際座標。 |
| W4 大招的預告軌跡用的是 W2 的物理（會從牆壁、天花板、方塊反彈），但 W4 實際上撞牆即停並打穿方塊，預告與實際落點不符。 | 預告用該首領真正的運動規則模擬。 |
| 首領的預告帶由幾百個半透明方塊疊成，疊起來幾乎不透明，蓋住整個畫面。 | 大幅降低濃度，另畫一條虛線中心線。 |
| 彈道預覽只會停在三種方塊上，會穿過被吃過的方塊與玻璃。 | 停在任何實心方塊、尖刺或地圖邊緣。 |
| 吞噬動畫對被吃過的彈力方塊用錯顏色。 | 依方塊種類上色。 |
| 介面用表情符號當圖示，外觀取決於系統字型，缺字時顯示成方框。 | 圖示全部用向量繪製；中文字型隨遊戲發佈。 |
| 畫面固定 960×540 再放大，放大後模糊。 | 以實際解析度向量繪製。 |
| 連續出現的提示訊息，前一則的計時器會提早關掉後一則。 | 新訊息取代舊訊息並重新計時。 |
| 介面上有寫死的假狀態文字（「SYSTEM STABLE: 60 FPS」、「Viewport: Fixed 800×600」、「BROWSER ENGINE」）。 | 不移植。 |
| 第 50 格以「世界首領挑戰」呈現，但沒有首領；沒有專屬配置的格子也沒有任何標示。 | 首領尚未製作的格子與空白格子都有標記（見第五節）。 |
| 沒有通關紀錄。 | 記錄已通關的格子並顯示在關卡卡片上；不做任何鎖定。 |
| 死亡時全螢幕純白閃光。 | 保留閃光但降低不透明度。 |
| 首領被填滿後可以吞噬，但畫面上沒有任何提示。 | 首領上方顯示提示文字。 |
| 子彈時間沒有上限，按住吐出鍵就能無限期以四分之一速度進行，首領戰也一樣。 | 一格能量可用 3 秒，放開後約 4 秒回滿；用完後彈道線仍在，只是時間恢復正常。史萊姆頭上有能量條，慢動作時畫面邊緣會泛藍。這是「模擬被推進得多快」的規則，不屬於模擬本身，所以不影響對照測試。 |
| 過關與死亡畫面瞬間出現；進入關卡沒有任何提示；對話框與關卡卡片瞬間出現。 | 過關與死亡的標題會落下、說明文字依序淡入；進入關卡時顯示關卡標題；對話框彈出、關卡卡片依序進場並在滑鼠移上時微微放大；選單背景的光暈緩慢飄移，標誌的史萊姆會呼吸與眨眼。 |
| 全螢幕只能從設定畫面切換。視窗大小固定，在小螢幕上會超出桌面。 | F11 或 Alt+Enter 隨時切換全螢幕（暫停與對話框中也有效），並與設定同步；F11 不能被綁成遊戲按鍵。視窗模式的大小依螢幕決定（可用桌面的八成、16:9、置中），並有最小尺寸。 |

## 四、關卡編輯器

| 網頁版的缺陷 | Godot 版的處置 |
| --- | --- |
| **未儲存的內容會無聲消失。** 切到測試遊玩、換格子、回選單都會重新載入存檔，沒存的編輯直接不見。 | 測試遊玩直接跑目前的工作內容，回來時原封不動；換格子、回選單、關閉視窗前若有未儲存的變更會先詢問。 |
| 測試遊玩中除了過關，沒有辦法回到編輯器。 | 暫停選單有「返回編輯」。 |
| 沒有復原。 | 復原與重做（一百步），一筆畫算一步。 |
| 快速拖曳滑鼠會漏格。 | 兩個取樣點之間補成連續直線。 |
| 右鍵擦除是把筆刷偷偷換成橡皮擦再換回來。 | 右鍵就是擦除，不動筆刷。 |
| 可以把方塊畫在玩家起點上，玩家會生在方塊裡。 | 起點那一格不能蓋上方塊；移動起點時會清掉該格。 |
| 用起點筆刷放的位置，和載入關卡時的位置差 3 個單位。 | 統一置中於格子。 |
| 調整地圖大小超出範圍時，引擎拒絕但介面仍顯示新數字。 | 超出範圍的數值會被夾住，到達上下限時按鈕停用。 |
| 在匯入文字框打字時，W A S D R 會被遊戲攔截，畫面還會跟著捲動。 | 文字框有焦點時不處理移動鍵。 |
| 要先存檔才能匯出；錯誤用瀏覽器的 `alert` 顯示。 | 直接匯出畫面上的內容；訊息顯示在畫面內。 |
| 匯入不檢查內容：任何以 `slime_maker_level_` 開頭的鍵都收，不檢查尺寸、字元、是否為矩形。 | 驗證格子編號、尺寸、字元；整包有一關不合格就全部不寫入，並說明原因。 |
| 存檔內容損毀時，載入關卡會直接讓遊戲當掉。 | 損毀的存檔會被忽略並改用內建關卡；在編輯器開啟那一格時會提示。 |
| 自訂存檔蓋掉某一格後，沒有辦法回到內建關卡。 | 「還原為內建關卡」。 |
| W1 首領格的土堆會被編輯器寫進存檔。 | 土堆屬於首領戰的佈置，只在遊玩時加上。 |
| 編輯器的鏡頭移動速度隨更新率變化。 | 以每秒速度計算。 |

## 五、沒有更動、需要設計者決定的觀察

關卡配置依規定一字未改。以下是轉換與測試過程中看到的情況，由設計者決定是否處理。

- **第 17 關最後一列少一個字元**（24 個字元，其他列 25 個）。缺的那格在網頁版與 Godot 版都被當成空氣。
- **第 8 關的上邊界有一個缺口**，玩家可以從那裡離開地圖。看起來像是刻意的。
- **第 21、22 關像是測試用的關卡**（第 21 關把每種方塊各擺一個）。
- **沒有專屬配置的格子**：23–29、31–39、41–50。它們使用通用的空房間（`DEFAULT_LEVEL_DATA`），起點走到終點沒有任何阻礙。Godot 版在這些格子上標示「空白關卡」，但仍然可以進入，過關後也照樣前往下一格。
- **World 5 沒有首領。** 第 50 格標示「首領尚未製作」。
- **第 10、30 格沒有專屬配置**，使用通用的首領競技場（`BOSS_LEVEL_DATA`）。

## 六、刻意保留的行為

這些看起來可能像缺陷，但改掉會影響現有關卡的解法或首領戰的難度，所以照原樣保留。

- **可以隔牆吞噬。** 吞噬射線只找可以吃的方塊，不會被鋼鐵或玻璃擋住，65 單位內隔著一格牆也吃得到。
- **首領戰的落石落地時變成隨機方塊。** 落石生成時帶有種類（大招還有四種花樣），但落地時一律重新抽籤，畫面上每顆也都是同樣的黑色方塊。原始碼註解明寫「落地時變成隨機方塊」與「Uniform black block rule」，這是設計，不是缺陷；生成時的種類只是沒被用到的殘留資料。
- **彈跳後可以在空中再跳一次。** 撞到彈力天花板後 24 tick 內、踩首領彈起後 30 tick 內可以起跳；踩彈力地板也寫了 24，但馬上被另一條規則改回 4。三處不一致，但往哪邊統一都會改變關卡的可行路線（放寬會出現跳關，收緊可能讓既有解法失效），所以維持現狀，留給設計者決定。
- **彈力方塊彈不彈取決於起跳點，不取決於撞擊速度。** 落下的高度從「離地那一刻的位置」算起，不到 32 單位就不彈。所以原地跳起再落回彈力方塊不會彈，從一格高走下來卻會。這讓玩家能站在彈力方塊上把它吃掉。
- **自訂存檔會取代同一格的內建關卡**，在「關卡」分頁玩到的就是自訂版本。這是設計者製作關卡的流程，所以保留，並在卡片上標示「自訂關卡」、提供還原功能。
- **W4 首領被吞噬時會定在原地**，即使當時在半空中。
- 所有玩法數值（重力、跳躍力、速度、後座力、首領的冷卻與機率）與網頁版相同，由對照測試保證。

## 七、會改變玩法的修正，以及需要實機確認的事

第一節的第 15、17、19、20 項不只是修錯，也會改變玩起來的結果，設計者試玩時請特別留意：

- **空中的水平後座力（第 20 項）** 讓玩家在空中朝旁邊吐方塊時會被推開約三格。它讓「靠後座力移動」在水平方向也成立，但也可能讓某些關卡出現原本沒有的捷徑。要調整力道，改 `PlayerSystem.RECOIL_CARRY`（並同步改對照基準的補丁）。
- **首領跳得更準（第 19 項）** 會讓 W1 與 W4 首領戰變難一些。
- **方塊打到首領會彈回來（第 15 項）** 讓 W4 首領戰的方塊比較不缺，也讓 W1 首領更容易把方塊吸回去。
- **子彈時間有上限** 讓首領戰無法全程慢動作。額度在 `BulletTimeGauge` 的兩個常數。

以下幾點只靠讀程式無法判斷，沒有更動：

- W3 首領的護盾彈落地會變成玻璃，玻璃不能吃，只能用方塊一換一打掉；打久了場地可能被玻璃堆滿。
- W2 首領休息加蓄力共 5 秒不動且碰了不會受傷，玩家可以直接吃掉它腳下的泥土讓它掉下去。這可能正是預期的解法。
- 嘴裡含彈力方塊時，走路碰到任何牆都會被彈開並鎖住操作 0.2 秒。
