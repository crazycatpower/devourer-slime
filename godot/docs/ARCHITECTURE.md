# 架構與規範

這份文件說明 Godot 版的組成方式、各層的責任，以及在這個專案裡寫程式要遵守的規則。

## 總覽

```
            ┌──────────── app ────────────┐   畫面切換
            │  MainMenu  GameScreen  EditorScreen
            └──────┬──────────┬──────────┬─┘
        ui / input │   game   │  editor  │        節點、輸入、畫面
            ┌──────┴──────────┴──────────┴─┐
            │   render (WorldView + 圖層)   │        只讀取模擬狀態來畫
            └──────────────┬───────────────┘
   autoload: Settings, LevelStore, Progress, AudioDirector   服務
            ┌──────────────┴───────────────┐
            │  core/sim   決定性模擬核心     │        純邏輯
            │  core/level 關卡資料           │
            └──────────────────────────────┘
```

依賴只能由上往下。`core/` 不認識節點、輸入裝置、繪圖或音效，也不使用任何 autoload，所以能在無頭環境下直接測試。

## 模擬核心（`src/core/sim`）

網頁版的手感來自它自訂的固定步長物理：整數格子加上軸對齊包圍盒，速度單位是「每 tick 幾個世界單位」。把它換成引擎物理會改變手感，所以這裡把它移植成一個獨立的模擬物件 `GameSim`。

- **固定步長**：`GameSim.step(input)` 前進一個 tick，一秒遊戲時間是 60 tick。模擬不看實際經過的時間。
- **輸入**：每個 tick 收到一個 `SimInput`（方向、跳躍、吞噬、射擊的按住狀態，跳躍按下與射擊放開這兩個邊緣，還有滑鼠在視野內的位置）。
- **輸出**：音效用 `sfx_requested` 訊號送出；其餘就是狀態本身，由繪製層讀取。
- **時鐘**：需要時間的玩法（首領擺盪、護盾公轉、蓄力閃爍）使用 `clock_ms()`，它由 tick 數算出，所以會跟著暫停和子彈時間一起停、一起慢。
- **亂數**：`SimRandom` 是自己的決定性產生器。同樣的種子加上同樣的輸入會得到完全相同的結果。純裝飾用的效果使用另一個 `fx_rng`，不會擾動玩法的亂數序列。
- **鏡頭**：鏡頭位置屬於模擬，因為玩法會讀它（瞄準點是滑鼠位置加上鏡頭位置，首領落石只落在看得見的欄位）。`update_camera()` 每個 60 Hz 畫面呼叫一次。

檔案分工：

| 位置 | 內容 |
| --- | --- |
| `game_sim.gd` | 狀態的擁有者、`step()`、共用查詢（吞噬目標、實心方塊、方塊損耗） |
| `state/` | 純資料：玩家、首領、護盾、飛行方塊、粒子、落石、鏡頭、輸入 |
| `systems/player_system.gd` | 移動、跳躍、吞噬、吐出 |
| `systems/collision.gd` | 玩家對方塊的碰撞與彈跳 |
| `systems/projectile_system.gd` | 飛行方塊的掃掠、反彈、落地成方塊 |
| `systems/falling_block_system.gd` | 首領震落的方塊 |
| `systems/boss_system.gd`、`boss_collision.gd` | 首領共用邏輯、玩家與首領的接觸 |
| `bosses/boss_world_N.gd` | 四個首領各自的行為 |

首領種類由 `BossState.Kind` 表示，「哪一格是哪個首領」只記在 `LevelLibrary` 的一張表裡。

## 遊戲畫面的時間模型（`src/game/game_screen.gd`）

- `_physics_process` 固定每秒 60 次。每次把「遊戲速度 × 子彈時間倍率」加進累加器，累加器每滿 1 就跑一個 tick。所以正常速度下每個物理畫面剛好一個 tick，2 倍速兩個，子彈時間約四個畫面才一個。
- `_process` 依螢幕更新率執行，用累加器的小數部分在「上一個 tick」與「這一個 tick」之間內插後繪製。
- 結果：遊戲速度與螢幕更新率無關，高更新率螢幕上畫面依然平滑。

子彈時間是「模擬被推進得多快」，不是模擬的一部分：模擬只記錄玩家是否正在瞄準，放慢多少、能放慢多久由遊戲畫面決定。額度由 `BulletTimeGauge` 以真實秒數計算，所以加上額度不會改變任何模擬結果，對照測試不受影響。

輸入由 `PlayerInput` 收集。按下與放開的邊緣會保留到有 tick 消化它為止，所以子彈時間裡的短按不會漏掉，倍速時也不會被套用兩次。暫停或視窗失去焦點時會清掉所有按住狀態。

## 繪製（`src/render`）

遊戲裡沒有圖片素材，所有東西都是向量繪製。

- `WorldView`（Control）是看進關卡的視窗，寬度永遠是 1040 個世界單位。它擁有一疊 `WorldLayer`，依固定順序各畫一種東西：背景、方塊、彈道、飛行方塊、玩家、粒子、落石、首領、提示、編輯器輔助線。
- 圖層只讀取 `GameSim`，從不修改它。
- `Painter` 把 `draw_*` 呼叫包成有變換堆疊的畫筆（push / pop / translate / rotate / scale），文字會依螢幕上的實際大小點陣化，放大縮小都清晰。
- `TilePainter` 畫方塊；選單圖示、編輯器筆刷圖示、首領體內的方塊都共用它。
- 遊戲與編輯器共用同一個 `WorldView`。編輯器另外持有一個不會前進的 `GameSim`，只是讓視圖有東西可畫。

## 關卡資料（`src/core/level`、`src/services`）

- 文字格式沿用網頁版：字串陣列，一個字元一格（`@` 鋼鐵、`#` 泥土、`*` 彈力、`X` 玻璃、`O` 虛空、`~ > v <` 尖刺、`$` 終點、`P` 起點、`.` 空氣）。
- `LevelCodec` 在文字與 `LevelData`（格子加起點）之間轉換；`LevelValidator` 檢查外來資料。
- `LevelLibrary` 讀取內建關卡 `data/levels/official_levels.json`。這個檔案是產生出來的，**不可手改**。
- `LevelRepository` 管理玩家的自訂關卡（每格一個 JSON 檔，先寫暫存檔再改名）。一格有自訂存檔就玩自訂的，否則玩內建的。
- `SavePaths` 決定檔案放在哪裡；以 `--sandbox` 執行時全部導向 `user://sandbox/`。

## 介面（`src/ui`、`src/editor`、`src/app`）

- 每個畫面是一個場景（`.tscn`）加一支腳本，腳本用 `%唯一名稱` 取得節點。清單類的內容（關卡卡片、筆刷按鈕、按鍵列）由腳本產生。
- 畫面之間互不引用。畫面用訊號說出玩家想做什麼，`App` 決定接下來顯示什麼。
- 外觀集中在一份主題 `src/ui/theme/game_theme.tres`，它由 `tools/build_theme.gd` 產生。要改按鈕、面板、字級，改那支腳本後重新執行，不要手改 `.tres`。
- 從編輯器測試遊玩時，編輯器只是被隱藏而不是關閉，未儲存的內容與復原紀錄都會保留。
- 介面動畫集中在 `UiMotion`（對話框彈出、清單項目依序進場、滑鼠移上時放大）。它只動縮放與透明度，不動版面，而且控制項從第一幀起就能操作，沒有任何邏輯等待動畫結束。遊戲內的過關、死亡、關卡標題與慢動作效果由 `GameOverlay` 以真實時間繪製，同樣不影響模擬。
- 視窗行為在 `WindowController`：F11 與 Alt+Enter 切換全螢幕、依螢幕決定視窗大小、最小尺寸。是否全螢幕是一項設定，快捷鍵透過 `Settings` 切換，設定畫面因此保持同步。

## 音效（`src/audio`）

沒有錄音檔。`ToneSynth` 把振盪器掃頻離線算成 PCM，`SfxLibrary` 記錄每個音效的配方（頻率與包絡沿用網頁版）。背景音樂由 `MusicSequencer` 即時排程：音符是可循環的單一波形樣本，靠播放速度決定音高，每一幀更新音量包絡；首領戰會換成較緊張的和弦，並隨首領被填滿而加速。

## 測試策略

移植三千行物理與首領邏輯，光靠目測沒有說服力，所以用網頁版引擎本身當標準答案。

1. `tools/parity/make_reference.mjs` 讀入網頁版的 `GameCanvas.tsx`，切掉 React 元件、把瀏覽器相依換成假物件，在 Node.js 裡執行真正的原始引擎。
2. 一個有種子的機器人逐 tick 餵輸入給它，每個 tick 記下狀態：玩家與首領的位置速度與旗標、關卡與首領格子的雜湊、粒子與飛行方塊的數量與座標總和、鏡頭，還有這個 tick 播了哪些音效。
3. `tests/parity` 把同樣的輸入重播給 `GameSim`，逐 tick 比對，容許誤差 2e-5。

兩邊用同一個亂數演算法，所以連粒子位置都必須一致；任何一處抽亂數的順序或次數不同都會被抓到。

Godot 版刻意修掉的缺陷，凡是會影響模擬的，都在產生器裡以具名補丁（`REFERENCE_PATCHES`、`HARNESS_FIXES`）同步套用到參考引擎上。因此參考基準的定義是「網頁版引擎，加上清單上這幾項修正」，每一處偏差都有記錄與理由。

為了涵蓋笨機器人打不到的深處（首領後期階段、擊敗首領），部分情境使用不死玩家與「干預」：在指定 tick 對兩邊做相同的狀態修改，例如把首領的格子填滿。產生器會印出每個情境實際走過哪些首領狀態，方便檢查涵蓋範圍。

## 程式規範

- **型別**：所有變數、參數、回傳值都標型別。專案設定把未標型別、不安全的屬性與方法存取、不安全的呼叫引數、整數除法、窄化轉換、遮蔽變數、未使用的變數與參數都當成編譯錯誤。
- **風格**：遵循官方 GDScript 風格指南。Tab 縮排、`snake_case` 函式與變數、`PascalCase` 類別、`CONSTANT_CASE` 常數、私有成員以底線開頭。
- **一檔一類別**，有 `class_name`。autoload 腳本不取 `class_name`。
- **註解**：類別與公開 API 用 `##` 文件註解，說明用途與不明顯的理由；不寫只是複述程式碼的註解。程式碼註解用英文。
- **訊號向上、呼叫向下**：子節點用訊號通知，父節點直接呼叫子節點。
- **數值**：玩法數值集中在 `GameConstants` 與各系統檔案開頭的具名常數，不在邏輯中夾帶魔術數字。
- **模擬的座標與速度不用 `Vector2`**：它是 32 位元浮點數，會破壞與參考引擎的一致，位置與速度一律用分開的 `float`（64 位元）。格子索引可以用 `Vector2i`。
- **不設計關卡**：見 README 的「關卡資料」。測試只使用內建關卡，必要時在測試內直接改幾個格子當作情境佈置。

## 常見工作

**修改玩法數值或邏輯**　先確認是不是要偏離網頁版。若是，在 `make_reference.mjs` 加一條補丁並在缺陷文件記上一筆，重新產生參考軌跡，再跑 `tools\test.ps1`。

**新增首領**　在 `BossState.Kind` 加一種，寫 `bosses/boss_world_N.gd`，在 `BossSystem.update` 與 `BossCollision.resolve` 接上，在 `LevelLibrary` 的表裡指定它的格子，在 `BossLayer` 補上繪製。競技場使用既有的 `BOSS_LEVEL_DATA`。

**新增一種方塊**　在 `Tile` 加 id 與分類、`LevelCodec` 加字元、`TilePainter` 加畫法、`LevelEditor.Brush` 加筆刷。

**新增畫面**　一個場景加一支腳本，對外只用訊號，在 `App` 裡接上切換。
